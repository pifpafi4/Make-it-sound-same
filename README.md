# Make It Sound Same

Утилита для Windows, которая **заранее** приглушает громкость «неизвестных» приложений:
вы запускаете только что скачанную игру — и её оглушающее интро встречает вас на 5% громкости,
а не на 100%.

Название — «make it sound same»: приложения должны звучать одинаково тихо, пока вы сами
не решите иначе.

Лицензия — [MIT](LICENSE): при использовании кода проекта сохраняйте уведомление об авторских правах.

## Как это работает

1. Утилита через WASAPI (Windows Core Audio) следит за аудиосессиями устройства вывода по умолчанию.
2. Новая сессия → определяется процесс (`QueryFullProcessImageName`) → путь к exe.
3. Если пути нет в базе известных приложений — громкость сессии падает до 5% (настраивается)
   и повторно подтверждается через 300 мс / 1 с / 2 с (некоторые приложения сами перезаписывают громкость).
4. Приложение запоминается: при следующих запусках громкость **не сбрасывается**.
5. Если вы сами двигаете ползунок в системном микшере — утилита отступается (отслеживается по GUID-контексту изменений).

### Автоприглушение громкости (v2)

Физические dB SPL без микрофона измерить нельзя, поэтому используется **относительная шкала**:

1. Слушаете что-то комфортное → жмёте «Калибровать…» в настройках (5 секунд) — утилита
   запоминает опорный уровень. Измеряется **слышимый** уровень: метр пика потока сессии
   (`IAudioMeterInformation`, до фейдера) + громкость сессии + мастер-громкость устройства.
2. Сессии громче «опора + потолок» (по умолчанию 5 дБ) приглушаются до потолка,
   максимум на 12 дБ; при тиши — плавный возврат к вашей громкости (гистерезис 2 дБ).
3. «Доверенные» приложения, системные звуки, заглушённые и недоступные (admin) сессии не трогаются.
4. Если пользователь двигает ползунок во время прижима — новая громкость становится базой.
5. **Калибровать можно и при выключенном автоприглушении** — удобно для перекалибровки:
   выключили лимитер → выставили комфортную громкость → откалибровались → включили снова.

Управление — вкладка «Настройки», полоски уровня и бейдж «приглушено» — во вкладке «Приложения».

### Первый запуск

При самом первом старте (базы ещё нет) утилита «знакомится» с уже запущенными приложениями
**без приглушения** — Chrome и прочие не пострадают. Глушатся только приложения, запущенные после.
Удалите `known-apps.toml`, чтобы начать знакомство заново.

## Сборка и запуск

```bash
build.cmd                 # release-сборка → bin\miss.exe
build.cmd debug           # debug-сборка → bin\miss.exe
```

Или вручную: `cargo build --release` (exe в `target\release\miss.exe`).
Требования: Windows 10/11, Rust stable.

### Консоль и логи

Обычный запуск (`bin\miss.exe`, двойной клик) — **без консольного окна**; логи пишутся
в `%APPDATA%\make-it-sound-same\make-it-sound-same.log`.

Режим отладки — флаг `--debug`:

```bash
bin\miss.exe --debug          # из терминала: логи видны в этом же окне
bin\miss.exe --debug > l.txt  # перенаправление тоже работает
```

При `--debug` уровень логов по умолчанию `debug` (переопределяется переменной `RUST_LOG`).

### Отладочные примеры

```bash
cargo run --example enum_sessions   # список активных аудиосессий с путями и громкостью
cargo run --example tone            # «неизвестное приложение»: играет синус 440 Гц дважды по 3 с
cargo run --example tone -- --loud  # то же + поднимает свою громкость до 100% (тест лимитера)
```

## Интерфейс

Окно (egui) + иконка в трее:

- **Приложения** — активные сессии: слайдеры громкости, мьют, полоски уровня, статусы
  (доверенное / контролируется / системные / не опознан; «приглушено»; «недоступно» — процесс запущен с повышенными правами).
- **Известные** — база приложений: переключатель «доверенное» (никогда не трогать) и «Забыть»
  (снова считается новым, дефолт применится и к играющим сессиям).
- **Настройки** — масштаб интерфейса, громкость дефолта, задержки re-assert, скрытие системных звуков,
  автозапуск с Windows, поведение при закрытии окна, автоприглушение (вкл/выкл, потолок, калибровка).
- **Громкость** — справка по автоприглушению и текущая опора.

Конфигурация: `%APPDATA%\make-it-sound-same\` — `config.toml`, `known-apps.toml`, лог.

## Архитектура

Один крейт, модульная структура; вся работа с COM — в выделенном аудиопотоке:

```
src/
├─ audio/            WASAPI-слой (windows-rs 0.62)
│  ├─ mod.rs         AudioEvent/Command, движок-поток: bind устройства, rescan, применение политики
│  ├─ sessions.rs    реестр сессий, COM-колбэки IAudioSessionEvents/IAudioSessionNotification
│  ├─ binding.rs     дефолтное устройство: Activate(IAudioSessionManager2), имя из property store
│  └─ process.rs     pid → путь exe
├─ policy/
│  ├─ mod.rs         RuleEngine: события × конфиг → команды. Чистая логика, покрыта тестами
│  └─ loudness.rs    v2: peak→dBFS, EMA-сглаживание, Limiter (duck/гистерезис/возврат)
├─ config/           TOML-конфиг + база приложений (атомарная запись)
├─ ui/               окно на egui + трей (tray-icon, свой message pump)
├─ autostart.rs      HKCU\...\Run
└─ logging.rs        tracing: консоль + файл
```

Потоки: **аудио** (владелец COM, MTA; колбэки кладут в канал только простые данные,
правила и лимитер применяются мгновенно, метры опрашиваются на 10 Гц) ↔
**UI** (egui, слушает события, шлёт команды). Устройство по умолчанию отслеживается
опросом id (~1.5 с): в windows-rs 0.62 метод `IMMDeviceEnumerator::RegisterNotificationClient`
не сгенерирован. Скрытое в трей окно не крутит UI-цикл — поэтому «Показать» из трея
показывает окно напрямую через Win32 (`EnumWindows` + `ShowWindow`), а «Выход»
завершает процесс через страховочный watchdog.

## Ограничения и особенности

- **Процессы с повышенными правами**: сессии admin-приложений нельзя менять из не-админ процесса —
  такие сессии помечаются «недоступно»; запустите утилиту от админа, если нужно.
- Физические dB SPL без микрофона не измеряются — v2 работает с относительной шкалой (калибровка).
  Метр сессии измеряет пик потока до фейдера сессии: громкость сессии не влияет на измерение.
- Если приложение само меняет свою громкость в первые секунды — это неотличимо от действия
  пользователя, re-assert отменяется. Для 99% игр интро не регулирует громкость микшера.
